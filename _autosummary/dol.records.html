dol.records¶

Records: a queryable CRUD facade for the small rows beside the blobs (#80).

dol.content holds the content half of the content–metadata bifurcation (blobs addressed by ContentRef). This module is the record half: a collection facade with CRUD and query, the Python mirror of zodal’s DataProvider (@zodal/store), so a Python backend and a zodal frontend speak the same contract.

  • DataProvider — the protocol: get_list(params) -> ListResult, get_one, create, update, update_many, delete, delete_many, optional upsert and capabilities().

  • ListParams — structured sort / filter / search / pagination. Filters are zodal’s FilterExpression as plain dicts: {"field": "year", "operator": "gte", "value": 2020}, combined with {"and": [...]}, {"or": [...]}, {"not": ...}.

  • filter_to_function() / apply_query() — the client-side fallback for any backend that cannot push a predicate, a sort or a page down.

  • Capabilities — what a provider can do and push down, so callers degrade.

  • MappingProvider — the reference provider over any MutableMapping of id -> record (a dict, or any dol store of dicts, e.g. JSON files).

  • BifurcatedProvider — records in a provider, their large fields in a dol.content store, with ContentRef s in their place.

  • wrap_provider() — a provider seen through a record codec (encode / decode), the records analog of dol.wrap_kvs().

Stdlib only, like the rest of dol’s core.

>>> people = MappingProvider({})
>>> _ = people.create({"id": "ada", "name": "Ada", "born": 1815})
>>> _ = people.create({"id": "alan", "name": "Alan", "born": 1912})
>>> _ = people.create({"name": "Grace", "born": 1906})       # an id is generated
>>> res = people.get_list(ListParams(
...     filter={"field": "born", "operator": "gt", "value": 1900},
...     sort=[Sort("born", desc=True)]))
>>> [r["name"] for r in res.data], res.total
(['Alan', 'Grace'], 2)
>>> people.update("ada", {"born": 1816})["born"]
1816

class dol.records.BifurcatedProvider(metadata, content_store, *, content_fields, id_field='id', content_key=<function _default_content_key>)[source]¶

Bases: object

Records in a metadata provider, their large fields in a content store.

The record half of the content-metadata bifurcation: on write, the content_fields of a record go to content_store (bytes, via dol.content.put_content()) and the record keeps a ContentRef (its wire-form dict) in their place; on read the refs come back, light enough to list, and get_content() (or get_one(id, resolve_content=True)) fetches the bytes.

The metadata record is the commit point: content is written before the record that refers to it is (for a new record, the record is created first to learn its id, then compensated by deletion if a content write fails), and deleted after the record is gone (a failed content delete leaves an orphan blob, never a dangling ref).

>>> from dol.content import ContentRef
>>> clips = BifurcatedProvider(MappingProvider({}), {}, content_fields=["audio"])
>>> rec = clips.create({"title": "take 1", "audio": b"RIFF..."})
>>> ContentRef.from_json(rec["audio"]).item_id
'1.audio'
>>> clips.get_content(rec["id"], "audio")
b'RIFF...'
>>> clips.get_one("1", resolve_content=True)["audio"]
b'RIFF...'
Parameters:

  • metadata (DataProvider) – the DataProvider holding the records.

  • content_store (MutableMapping[str, bytes]) – a MutableMapping of bytes (a dict, a dol Files, S3…).

  • content_fields (Sequence[str]) – the record fields whose values are bytes to offload.

  • content_key (Callable[[Any, str], str]) – (record id, field) -> content store key.

class dol.records.MappingProvider(store, *, id_field='id', new_id=None, search_fields=None)[source]¶

Bases: object

A DataProvider over any MutableMapping of id -> record.

Queries run client-side (apply_query()) over the mapping’s values, so it suits small collections; a backend that can push queries down implements DataProvider itself. Records come back as copies carrying their id (the key) in id_field, so a store keyed by id alone works too. Ids are used as given (generated ones are strings).

Parameters:

  • store (MutableMapping[Any, Mapping[str, Any]]) – id -> record mapping (a dict, or a dol store of dicts).

  • id_field (str) – the record field holding its id (kept equal to the key).

  • new_id (Callable[[MutableMapping], Any] | None) – makes an id for a record created without one.

  • search_fields (Sequence[str] | None) – fields search looks in (default: every str field).

class dol.records.WrappedProvider(provider, *, encode=<function _identity>, decode=<function _identity>)[source]¶

Bases: object

A provider seen through a record codec (zodal’s wrapProvider).

decode turns a stored record into the app’s shape on the way out (get_list, get_one and every write’s result); encode turns the app’s (possibly partial) record into the stored shape on the way in. Queries (ListParams) are passed through unchanged, so they name stored fields. The analog of dol.wrap_kvs() for records.

>>> stored = MappingProvider({})
>>> app = wrap_provider(
...     stored,
...     encode=lambda r: {("tags_csv" if k == "tags" else k): (",".join(v) if k == "tags" else v)
...                       for k, v in r.items()},
...     decode=lambda r: {("tags" if k == "tags_csv" else k): (v.split(",") if k == "tags_csv" else v)
...                       for k, v in r.items()},
... )
>>> app.create({"id": "a", "tags": ["x", "y"]})["tags"]
['x', 'y']
>>> stored.get_one("a")["tags_csv"]
'x,y'
